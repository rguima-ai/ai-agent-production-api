1. ¿Cuál es el problema?

Un agente puede tardar entre varios segundos y minutos. Si FastAPI ejecuta el grafo dentro del mismo request, la conexión queda abierta, aparecen timeouts y el servidor desperdicia capacidad esperando al modelo.

Diseño bloqueante

POST /process llama al LLM y responde recién al finalizar. El cliente no sabe si sigue vivo y el servidor acumula conexiones largas.

Diseño desacoplado

La API entrega un ticket en milisegundos. Un worker ejecuta el agente por separado y el cliente consulta el resultado.

Asíncrono no significa instantáneo. Significa que el servidor puede hacer otro trabajo mientras espera entrada/salida, y que la tarea lenta no ocupa el ciclo de vida del request.

2. Arquitectura asíncrona

Cliente
→
FastAPI
→
Redis
→
Worker
  1. El cliente envía una consulta.
  2. FastAPI valida con Pydantic.
  3. La API guarda el estado PENDING.
  4. Recién después pone el job_id en la cola.
  5. Devuelve HTTP 202 Accepted.
  6. El worker extrae el identificador con BLPOP.
  7. Ejecuta LangGraph y actualiza Redis.
  8. El cliente consulta GET /tasks/{id}.

API y worker son procesos diferentes. Así podemos tener varias réplicas web y varios workers sin mezclar sus responsabilidades.

4. Human-in-the-loop

HITL significa que el agente se detiene antes de una acción crítica y espera una decisión externa. Ejemplos: transferir dinero, borrar datos, emitir un reembolso o enviar una comunicación real.

01

Clasificar

El Analista determina si hay un efecto costoso o irreversible.

02

Interrumpir

interrupt() pausa el nodo y el checkpointer conserva el hilo.

03

Aprobar

Una persona envía su decisión al endpoint de aprobación.

04

Reanudar

Command(resume=...) continúa el mismo thread_id.

Regla crítica: al reanudar, LangGraph ejecuta el nodo otra vez desde el principio. Nunca pongas un cobro, borrado o envío antes de interrupt(); el efecto debe vivir en un nodo posterior.

5. Observabilidad: ver dentro de la caja negra

Un HTTP 200 no garantiza una buena respuesta. El agente puede ignorar una herramienta, recuperar contexto irrelevante o inventar una cifra. Las trazas permiten reconstruir qué pasó.

ConceptoExplicación simpleEjemplo
TraceEl viaje completo de una solicitud.Desde que el worker toma el job hasta el informe final.
SpanUna unidad de trabajo dentro de la traza.Supervisor, llamada LLM, búsqueda o herramienta.
RunUna ejecución de un Runnable de LangChain.Una invocación concreta de un modelo.
EvalUna señal de calidad del resultado.Fidelidad, relevancia o precisión de contexto.

Phoenix vs. LangSmith

Arize Phoenix

Open source, local-first y basado en OpenTelemetry/OpenInference. Es compatible con distintos frameworks y puede mantener las trazas en tu infraestructura.

LangSmith

Integración natural con LangChain/LangGraph, debugging de prompts y creación de datasets a partir de ejecuciones.

Esta entrega usa Phoenix local. El worker crea un span raíz por job y la instrumentación automática agrega las llamadas de LangChain y OpenAI.

6. Latencia, tokens y costos

El promedio puede esconder usuarios con una experiencia muy mala. Por eso observamos percentiles.

p50

La mediana: la mitad de las ejecuciones fue más rápida y la otra mitad más lenta.

p95

El 95% terminó antes de ese valor; el 5% más lento quedó por encima.

Tokens

Entrada y salida consumidas por cada invocación del modelo.

Costo

La plataforma lo estima usando modelo y tokens observados. No existe en una simulación sin LLM.

La prueba de carga envía cinco tareas con asyncio.gather. Phoenix muestra el costo por ejecución y la latencia; el script también calcula un p95 HTTP local para contrastar.

7. Qué construimos

  1. POST /tasks crea y encola sin ejecutar el agente.
  2. GET /tasks/{id} permite polling.
  3. POST /tasks/{id}/approve reanuda un checkpoint.
  4. El Supervisor delega en Investigador, Analista, Aprobación y Síntesis.
  5. Redis persiste tanto el job como el estado de LangGraph.
  6. El worker convierte excepciones en FAILED.
  7. Phoenix recibe trazas y spans.
  8. Docker Compose levanta Redis, Phoenix, API y worker.
  9. Un modo simulado permite probar sin tokens; OpenAI produce la evidencia real.

8. Errores comunes

LLM dentro del endpoint

Convierte un request corto en una conexión larga y frágil.

Encolar antes de guardar

El worker podría leer un ID cuyo registro aún no existe.

Excepción sin FAILED

El usuario seguiría consultando para siempre un job RUNNING.

Efecto antes del interrupt

Podría repetirse al reanudar el nodo.

Solo mirar promedios

Oculta las ejecuciones lentas; observá p95 y p99.

Confiar solo en trazas

La observabilidad complementa, pero no reemplaza tests y revisión humana.
